# Aus Gov Data Explorer — Engineering Build Plan (PLAN.md)

This document tracks technical decisions, architecture, schema trade-offs, guardrails, and implementation milestones for the **Aus Gov Data Explorer** (AI-Powered Analytics App).

---

## 1. Project Overview & Objectives

- **Goal**: Enable exploratory data analysis of official Australian government data using natural language, returning interactive charts, verified SQL, and factually grounded analytical insights.
- **Key Tenet**: Disciplined AI engineering — ensuring mathematical and factual reliability over hallucinated conversational answers.
- **Portfolio Context**: Project 3 in a portfolio alongside an agentic app (FastAPI + React) and a text-to-SQL fine-tuning project. Code style maintains standard FastAPI + React/Vite conventions.

---

## 2. Dataset Selection & Ingestion Strategy

### Dataset Identified
- **Source**: Australian Bureau of Statistics (ABS), *Labour Force, Australia* (Catalogue 6202.0)
- **Table**: Table 010 (*Labour force status by Sex, State and Territory - Trend, Seasonally adjusted and Original*)
- **Period**: Monthly from February 1978 to July 2026 (~48.5 years of monthly data).
- **Download Date**: September 2026
- **Source URL**: `https://www.abs.gov.au/statistics/labour/employment-and-unemployment/labour-force-australia/jul-2026/62020010.xlsx`

### Dimensions & Metrics Extracted
- **Regions**: `Australia`, `New South Wales`, `Victoria`, `Queensland`, `South Australia`, `Western Australia`, `Tasmania`, `Northern Territory`, `Australian Capital Territory`.
- **Metrics**: `Unemployment rate` (%), `Participation rate` (%), `Employment to population ratio` (%), `Employed total` ('000), `Unemployed total` ('000), `Labour force total` ('000).
- **Series Adjustments**: `Seasonally Adjusted` (default headline), `Trend`, `Original`.
- **Sexes**: `Persons` (headline aggregate), `Males`, `Females`.

### Data Quality & Cleaning Decisions
1. **Header Normalization**: Stripped leading markers (`> New South Wales` $\rightarrow$ `New South Wales`).
2. **Missing & Empty Cells**: Skips metadata rows and ensures all values are converted to proper floats.
3. **Database Indexing**: Built indexes on `(metric_name, region, date)`, `(metric_name, date)`, and `(year)` in SQLite for sub-5ms query response times across 433,008 observations.
4. **Pre-computed Canonical View**:
   - `labour_force_monthly`: Pre-filtered to `sex = 'Persons' AND series_type = 'Seasonally Adjusted'`, dramatically simplifying the SQL queries generated by LLMs.
   - `regional_unemployment`: Direct shortcut view for unemployment rates.

## 3. Architecture & Tech Stack

```
[ React 19 / Vite Frontend ] 
         │  (HTTP /api/query)
         ▼
[ FastAPI Backend Engine ]
   ├── Intent Classification & Refusal Gate
   ├── Schema Context Builder
   ├── LLM NL->SQL Engine (OpenRouter API + Local Fallback)
   ├── SQL Validation Layer (sqlglot AST validation)
   ├── SQLite Execution Engine (query_only, 3.0s timeout, 1000 row cap)
   ├── Deterministic Chart Selector Heuristic
   └── Grounded Insight Synthesizer (Code stats calculation + constrained LLM narration)
```

- **Backend**: Python 3.11 / FastAPI, Uvicorn, SQLite3, `sqlglot`, `pandas`, `httpx`.
- **LLM Provider**: OpenRouter (`https://openrouter.ai/api/v1/chat/completions`). Configurable model (e.g. `meta-llama/llama-3.3-70b-instruct:free`, `google/gemini-2.0-flash-exp:free`).
- **Frontend**: React 19, Vite, Tailwind CSS, Recharts, Lucide Icons.

## 4. Guardrails & System Defenses

### Guardrail 1: SQL AST Validation (`sqlglot`)
- Queries are parsed into Abstract Syntax Trees using `sqlglot`.
- Statements that are not strictly single `SELECT` expressions (`DROP`, `DELETE`, `UPDATE`, `INSERT`, `ATTACH`, multi-statements) are intercepted and rejected prior to execution.
- Only tables/views on the strict allowlist (`labour_force`, `labour_force_monthly`, `regional_unemployment`, or internally defined CTEs) are permitted.
- Enforces row cap (`LIMIT 1000`) and SQLite read-only mode (`PRAGMA query_only = ON`).

### Guardrail 2: Deterministic Chart Heuristics
- The LLM is **never** asked to choose or configure chart parameters.
- Deterministic code analyzes column types and cardinality:
  - Date + single numeric $\rightarrow$ Line Chart.
  - Date + categorical grouping (multi-region) $\rightarrow$ Multi-line Comparison Chart.
  - Categorical + numeric $\rightarrow$ Ranked Bar Chart.
  - Single scalar $\rightarrow$ KPI Card.

### Guardrail 3: Strictly Grounded Insight Narration
- Summary statistics (min, max, average, start/end dates, absolute change, % change, rankings) are computed exclusively by Python code from the SQL result set.
- The LLM is provided only this computed statistical dictionary and an inflexible prompt forbidding the invention, extrapolation, or calculation of any figures.
- If OpenRouter is unavailable or unconfigured, a deterministic template engine crafts the sentence directly from the stats dictionary.

### Guardrail 4: Explicit Refusal Path
- Rather than hallucinating answers to out-of-scope or subjective questions:
  - **Causal queries** ("Why did unemployment rise in NSW?") are refused because observational survey tables do not record policy or economic drivers.
  - **Ambiguous queries** ("What is the worst region?") prompt the user for clarification with specific suggested metrics.
  - **Predictive queries** ("What will rates be in 2035?") are refused as future forecasting is outside the scope of historical records.
